|---|---|---|

## Conventions

- Current schema version is `0.1`.
- JSON uses deterministic snake_case property names and string enums.
- DTO validation rejects unsupported enum values, malformed identifiers, non-positive sequences, non-UTC timestamps, and oversized heartbeat payloads.
- Deserialization ignores additive optional fields so older readers can safely accept newer payloads when required fields remain compatible.

## Idempotency-key convention

Retryable agent-to-cloud writes MUST include an `Idempotency-Key` HTTP header. The value is an opaque stable key generated by the agent and scoped to the tuple `(agent_id, idempotency_key)`; it MUST NOT encode customer, LAN, credential, or device-secret data.

For event-batch submission, the idempotency key MUST equal `batch_id`. The batch payload is therefore retried with the same `batch_id` and the same `Idempotency-Key` value until the cloud acknowledges acceptance or a permanent validation/authentication error is returned. A duplicate submission with the same `(agent_id, Idempotency-Key)` and byte-equivalent canonical payload is expected to return the original accepted result without creating additional events, incidents, notifications, or audit-side effects. A duplicate key reused with different payload content is a contract conflict and must be rejected with a stable machine-readable error code.

Event batches require events to match the batch `agent_id` and `property_id`. Event sequences in a batch are ordered and contiguous: the first event sequence equals `first_sequence`, each subsequent event increments by one, and `last_sequence` equals `first_sequence + events.length - 1`.
